# AGENTS.md — Dash OS (Kindle PW2 "wario")
Minimal custom OS for a Kindle Paperwhite 2 (i.MX6SL, "wario") that boots from
the **stock MBR**: the stock lab126 3.0.35 kernel, with the **EPDC e-ink panel
built into the kernel**, is the boot and debug channel. `runit` is PID 1; p1
(`dash-root` ext3) holds the rootfs; a service paints the panel. No serial,
ever.

The init system comes up and `Hello World!` renders on the panel.

## Read first

- **`README.md`** — what it is, build, layout.
- **`docs/DEVICE.md`** — device manual: eMMC map, bootmode/IDME, SDP/fastboot
  recovery, host environment.
- **`docs/RUNBOOK.md`** — build + install runbook.
- **`docs/pinned-inputs.md`** — pinned kernel / busybox / runit / waveform
  provenance, and where the binary inputs live.
- **`CHANGELOG.md`** — what each release contains. This file and the docs hold
  facts and hard-won lessons; **`CHANGELOG.md` holds release information**.

## Layout

```
README.md  VERSION  CHANGELOG.md  Makefile  build.sh  Containerfile
BUILD-IMAGE.lock           the build environment, pinned by digest
AGENTS.md                  this file: the agent rule sheet
docs/DEVICE.md             the device/recovery manual
docs/RUNBOOK.md            build + install runbook
docs/pinned-inputs.md      pinned-input provenance
.github/workflows/         ci, PR commands, release finalisation
.github/scripts/release.py version arithmetic + CHANGELOG rewrite (testable)
recovery/                 SDP/fastboot + bootmode tooling; mk-patched-fastboot.py
                          is REQUIRED to reach fastboot while IDME bootmode
                          says diags
base-kernel/              the pinned main-slot kernel's DECLARED config
                          (config-declared.txt). The kernel bytes are private.
third-party/busybox/      applets.txt only (the binary is private)
overlay/                  the authored rootfs tree (etc/, service/)
src/                      Rust sources, cross-compiled into the rootfs
build/  artifacts/        [gitignored] staging + built images, regenerated by build
```

**No binaries are committed here.** The kernels, busybox, runit, the e-ink
waveform and the stock U-Boot are Amazon firmware extracted from a device, so
they are not redistributable and live in the **private `kindle-dash-pins`
repo**. `make pins` clones it at the matching tag and materialises the files at
the paths `build.sh` already reads. Stock WiFi modules and firmware are not in
either repo; they live beside them at `~/Documents/kindle-dash-assets/`.

## Versioning

- SemVer, no `v` prefix. `VERSION` is the single home. `/etc/dash-release` in
  the rootfs is **generated from `VERSION` during the build** — it is never
  authored, and the panel reads that file, not a literal in a script.
- **`CHANGELOG.md` is the release record.** An `## [Unreleased]` section sits at
  the top with a placeholder; every PR replaces the placeholder with what it
  changes, and a release command moves that text under the new version heading.
- `0.N.0` = the release slot: a shipped update with a new device-visible change.
- `0.N.M` (patch) = a fix-only release: a bug and no new content. Patch is not
  the slot for "a small update" — minor is.
- **`1.0.0` is a decision, not a date.** `!release-major` graduates `0.x` to
  `1.0.0` mechanically; whether to take that step is a judgement about WiFi,
  SSH, a UI framework and a tree that still reproduces from pinned inputs.
- **Tags are immutable.** Deletion and updates are blocked by a repository
  ruleset, including before 1.0.0. A bad release is fixed by a new patch
  version, not by moving a tag.
- A release is **two SHAs**: this repo at tag `X`, and the pinned-inputs commit
  named in `PINS.lock`. Both, plus the rootfs content fingerprint, are recorded in
  the tag annotation, so one tag fully determines the release.
- **The pins repo has no tags, and must not acquire them.** A commit SHA is
  already immutable and content-addressed; a per-release tag is an alias that can
  only fall out of sync, and every release has to write it or be one-sided. What
  makes the SHA stable is protecting that repo's default branch — no force push,
  no delete — plus `make verify`'s SHA256SUMS. Changing pins means editing the one
  `sha =` line in `PINS.lock`, in a PR.

## Release process

No change reaches `main` by being pushed to it.

1. Branch `feature/…`, `fix/…` or `chore/…`, open a PR.
2. `CHANGELOG.md`'s *Unreleased* placeholder is replaced with what the PR
   changes. Required check `changelog` enforces this.
3. `make test`, `make build` and `make fingerprint` run in CI. Required checks
   are `changelog`, `test`, `build`.
4. `!approve` on the PR records approval for the current head commit, as the
   required status check `approved`. (GitHub does not count self-approval, and
   this repository has one person, so approval is a deliberate recorded act
   rather than GitHub's review feature.)
5. `!release-patch`, `!release-minor` or `!release-major` on the PR. The command
   refuses — with a comment on the PR — unless `approved` is present and all
   three checks passed on the head commit. It then reports the required
   `release-gate` status and squash-merges. **That status is why the merge
   button is inert on an ordinary PR**: the ruleset requires `release-gate`,
   which only a release command ever produces.
6. The squash commit carries `Release-Intent:` in its message. The push to
   `main` triggers `release-finalize`, which bumps `VERSION`, rewrites the
   CHANGELOG, builds, and tags this repo. Nothing about a version number is
   decided by a human typing it into a file.

Tags are created **after** the build succeeds, never before. The bump commit
ends `[skip-bump]` so the push it makes cannot re-trigger itself.

Required secrets: `DASH_PINS_TOKEN` (read/write on the private pins repo) and
`DASH_RELEASE_TOKEN` (a fine-grained PAT, admin, contents read/write — needed
because the ruleset's admin bypass is what lets the bump commit land).

**Honest limits.** Branch rules bind everyone except an admin: you, or your
PAT, can always bypass `main`. And a PR from a fork cannot run `build`, because
GitHub withholds secrets from forks; bring the branch to this repository.

## Golden rules

1. **Nothing reaches `main` except a release.** A PR plus `!approve` plus
   `!release-*` is the only path in; the tag is what makes it a version. Never
   push to `main`, never merge by hand, never move a tag — fix forward with a
   patch. Built images are **not** committed: the pinned inputs + `overlay/` +
   `src/` are the version; `make build` regenerates `artifacts/`. Past version:
   `git checkout <tag> && make pins && make build`.
2. **One variable per device cycle.** Change one thing, boot, read back, decide.
   Log each step to `/var/log/dash.log` before the risky call.
3. **Panel is the device output** (serial banned). The machine-readable channel
   is `/var/log/dash.log`, readable from the Mac at
   `/Volumes/dash-root/var/log/dash.log` in diags.
4. Keep the stock MBR / partition layout: p1 root LBA 65536 (350 MiB), p4 user
   FAT32, p2/p3 untouched. Boot main slot @ `0x41000`, diags slot @ `0xE41000`.
   **Never write an MBR.**
5. Writing the rootfs: the `seek` depends on the node. The slice
   `/dev/rdiskNs1` **is** p1, so it takes `seek=0`; the whole-disk node needs
   `seek=65536` (p1's start in 512-byte sectors), adjusted for block size
   (`bs=1m seek=32`). Slice + `seek=65536` double-offsets and lands the image
   32 MiB into p1. Always verify the read-back md5 before booting.
6. Kernel invariant: EPDC **built-in** (`CONFIG_FB_MXC_EINK_PANEL=y`).
7. Real E60_V220 waveform is REQUIRED (1,240,775 B; gz `30f926d9…`). The
   placeholder 650-B firmware = white-screen freeze. The rootfs also carries it
   at `/lib/firmware/imx/epdc_E60_V220.fw`.
8. Keep EPDC powered between updates: `echo -1 > …/imx_epdc_fb/mxc_epdc_pwrdown`
   (written in runit/1). Panel ABI: MXCFB_SEND_UPDATE `0x4048462E`,
   MXCFB_WAIT_FOR_UPDATE_COMPLETE `0xC008462F`, GC16=2, FULL=1,
   FB_POWERDOWN_DISABLE = -1.
9. Main boot path: no sleeps (poll instead).
10. Kernel release string must stay `3.0.35-lab126` — the vermagic the stock
    `.ko` files were built against, which the WiFi milestone depends on.
11. Known-good baseline: main kernel `7c5638e9…` (real waveform baked in), diag
    `284d07f3…`.
12. **Panel update params are conservative, always.** `hist_bw=0`, `hist_gray=0`,
    `temp=0`; the automatic-temperature + histogram path does not return. `screen`
    has one update path on purpose.
13. **Nothing writes outside the filesystem.** No raw-LBA writes, ever. The eMMC
    below p1 holds the kernel images (main LBA 520–5868, diags LBA 29192–36571).
14. **This CPU is a Cortex-A9 (VFPv3-D16), not VFPv4.** Any binary using
    `vfma`/`vfms`/`vfnma`/`vfnms` dies with an illegal instruction. `build.sh
    check-float` enforces this; do not disable it.
15. **Userland must be static.** The rootfs has no libc and no dynamic loader.

## Device runbook

Full procedure: `docs/DEVICE.md`; the current version's runbook is
`docs/RUNBOOK.md`. Enter fastboot via SDP (power button broken: battery pull +
short pads):

```
uuu -lsusb                                      # expect MX6SL 15a2:0063
cd recovery && sudo uuu boot_patched_fastboot.uuu   # not the stock U-Boot
```

Flash the kernels (`diags_kernel` is the diags slot; `diags` is p2):

```
fastboot flash kernel       artifacts/main-uImage    # 0x41000
fastboot flash diags_kernel artifacts/diag-uImage    # 0xE41000
python3.14 recovery/fastboot-setvar-reboot.py diags  # not: fastboot setvar
```

Install the rootfs (device in diags, whole disk exported as `/dev/rdiskN`):

```
sudo diskutil unmountDisk force /dev/diskN
sudo dd if=artifacts/dash-rootfs.img \
        of=/dev/rdiskNs1 bs=1m seek=0 conv=notrunc
sudo dd if=/dev/rdiskNs1 of=/tmp/p1.img bs=1m count=64   # verify, see rule 5
md5 -q /tmp/p1.img artifacts/dash-rootfs.img
```

**Verify the read-back md5 matches before booting** — `diskutil` cannot tell a
partial write from a complete one. Then `python3.14
recovery/fastboot-setvar-reboot.py main` to boot.

## Reading a boot without serial

- **the panel** — primary; `docs/RUNBOOK.md` says what it shows.
- **`/var/log/dash.log`** on the rootfs; in diags macOS auto-mounts p1 read-only
  at `/Volumes/dash-root`:

  ```
  cat /Volumes/dash-root/var/log/dash.log
  ```

No raw-LBA markers, ever: they overlap the main kernel (LBA 520–5868) and
silently corrupt it.

## Build tooling (build image)

- One build image, `Containerfile`, built by `make env` (tag keyed to its
  sha256; `BUILD-IMAGE.lock` records the image **id** and the registry
  **digest**).
- **The build environment is an input, not a recipe.** The same `Containerfile`
  text yields different packages once Ubuntu's archive moves on, so the image is
  pinned by digest and `make env` refuses to build against an image that is not
  the pinned one. `make env-bump` (rebuild, republish, re-pin) is a deliberate,
  reviewed act, not a side effect of `make build`. Override a mismatch only with
  `ALLOW_IMAGE_DRIFT=1`.
- One tool: `build.sh` (multi-call) -- `build`, `userland`, `test`, `rootfs`,
  `check-float`, `fingerprint`, `lock-env`, `hashes`, `verify` -- driven by
  `make`.
- Userland language: Rust. `rustc` cross-compiles with
  `--target arm-unknown-linux-gnueabi` (armel, soft-float) and **no external
  crates** -- the handful of syscalls are declared by hand, so the build stays
  offline and there is no lockfile to drift.
- Tests: `make test` runs `rustc --test` on the image's **host** target. No Cargo
  and no crates; the image needs a native `gcc` + `libc6-dev` for this, which is
  why they are in the `Containerfile` by name.
- Pin the flags in `build.sh`: `-O --edition 2021`, and above all
  `-C target-feature=+crt-static` (the rootfs has no dynamic loader).
- `arm-linux-gnueabi-gcc` stays in the image as the rustc **linker driver
  only**; it supplies the cross crt objects and `-lc`. No C is compiled.
- The Rust toolchain version is pinned in `Containerfile` (`ARG RUST_TOOLCHAIN`).
- ext3 images + fingerprints: `e2fsprogs` 1.47 in the same image. Every packaged
  image must pass `e2fsck -fn` before it is allowed out of `build.sh`.
- **The kernel cannot be rebuilt**: the Amazon GPL source is not here, so
  `base-kernel/` and `base-diag/` are pinned bytes.

Build notes learned the hard way:

- **Content-reproducible, not byte-reproducible.** mke2fs 1.47 ignores
  `SOURCE_DATE_EPOCH`, so two builds differ in timestamp bytes; `make
  rebuild-check` proves the content is identical. The fs UUID
  `d4a50001-…-000000000001` is pinned.
- **The fingerprint is the release assertion.** The rootfs sha256 changes every
  build, so the *content fingerprint* is what a tag records. If the fingerprint
  of a tagged release ever changes, something got in that is not pinned.
- **macOS `tar`** synthesises AppleDouble `._*` members and `.DS_Store` is a
  real file; both are rejected at staging time.
- **Assert on the built artifact, not the staging tree** (an exec bit was once
  lost on the way in and shipped 0644).
- **A verification tool must be able to fail**; `build.sh fingerprint` prints
  mode *and* hash per entry so an empty result can't report success.
- **Do not swallow errors in reproducibility-critical steps.** A
  `find … touch … || true` hid the fact that BSD `touch` rejects `@epoch`, so the
  mtimes were never pinned at all. `touch -t 202601010000` with `TZ=UTC` is the
  portable form.
- **Avoid apostrophes in single-quoted `bash -c` bodies** — they split host from
  container.
- **A black panel that exits 0 is the worst failure mode there is.** The
  renderer whitened `bytes_per_pixel` bytes per row instead of the visible row
  width; the driver stride (768) is wider than the panel (758), so 767 of every
  768 bytes stayed at their power-on zero. The e-ink update still succeeded and
  the process still returned 0, so nothing on the device said so. It is now
  `fill_len()` with a unit test.
- **A literal newline inside a `run: |` block ends the YAML scalar.** A bash
  multi-line string whose continuation lines start at column 1 turns the rest of
  the step into a YAML syntax error. Use `printf` with explicit `\n`.
- **Validate workflow YAML before pushing it.** `ruby -ryaml` locally, and
  `bash -n` on every extracted `run:` block.
- **A YAML scalar may not begin with `!`.** `!` is the *tag indicator*, so
  `- name: !approve -- record approval` is not a string starting with `!approve`:
  it is a tagged node, and the token is silently dropped (Ruby reads the name as
  `"-- record approval"`). GitHub then rejects the whole workflow at schema
  validation, and the only symptom is a run with **0 jobs that fails instantly
  and logs nothing**. Quote such names. This killed the entire release flow once;
  `ruby -ryaml` alone did not catch it, because Ruby parses it happily.

## USB maintenance SSH and future WiFi

- **SSH over USB Ethernet** is the maintenance/debug channel; future WiFi is an
  operational network, not a prerequisite for debugging it. No serial, ever.
- Load only the pinned ARC gadget dependency closure; no forced module loading.
  Main boots never export mass storage. Diagnostics remains independent recovery.
- Dropbear/dropbearkey are static external builds, pinned as binaries with their
  exact upstream source hash and external build recipe. No C is compiled here.
- Canonical release images contain no device keys or seeds. Provision a separate
  image with an explicit public key and fresh per-device seed; never clone it.
- Passwords and forwarding are disabled. Bind only to `192.168.15.244:22`.
  Missing provisioning or entropy disables SSH without blocking the panel.
- Runtime seed/host-key state is private (0700 directories, 0600 files), outside
  release fingerprints; flashing a canonical image removes that device state.
- WiFi needs stock `ath6kl_sdio.ko` + `cfg80211.ko` + `ath.ko` from
  `~/Documents/kindle-dash-assets/modules/` — ath6kl is compat-wireless, **not in
  the Amazon GPL drop** — so it only loads if the vermagic stays
  `3.0.35-lab126` (`CONFIG_MODULE_FORCE_LOAD` is the escape hatch).
- Firmware at `/opt/ar6k/target/AR6003/hw2.1.1/bin`.
- `udhcpc` is in busybox; `wpa_supplicant` and dropbear must be built static.
- No RTC — set the time before anything cert-based works.

## Git discipline

- **One commit per version, then an annotated tag.** Never rewrite a tagged
  commit; `git checkout <version> && make build` is the way back.
- Pinned inputs are committed **gzipped** (`*.gz` twins), with `SHA256SUMS` of
  the RAW bytes (what gets dd-ed to the device). The e-ink firmware is already
  gzip and is committed as-is.
- **Built images are not committed.** `.gitignore` keeps `build/` and
  `artifacts/` out; raw pinned binaries and stock dumps stay on disk only.
